# 参考玩法可行性评估与扩展方案

> 评估对象：农场/渔场类玩法清单（养鱼、收获换资源、鱼塘升级、商店、抽奖配对、珍珠来源、好友互动）
> 评估基准：`wechat-game` 0.11.0（阴阳师和风 + 图鉴 + 招财贝壳 + 鱼塘钓鱼仓库）
> 结论性质：先出方案，不含代码改动

---

## 一、结论速览

| # | 参考玩法 | 我们的现状 | 判断 | 建议做法 |
|---|---|---|---|---|
| 1 | 养鱼：鱼苗→幼鱼→成熟，**成熟才能收取** | 三阶段已实现（`stageOf`/`stageName`），但任何阶段都能折价卖 | 可加（改造） | **保留随时卖**，另给「成熟收获」额外加成，不做硬门槛 |
| 2 | 收获换资源：金币鱼 / 点券鱼分工 | 只有鱼币；S 币骨架存在但**没有任何产出来源** | 部分可加 | 先做「低价快周转鱼」，点券暂不接真实付费 |
| 3 | 鱼塘升级：等级越高可养越多，**碎片**升级 | `pondLv` 存在但只按稀有度分 3 档，升级入口未开放；鱼位由仓库等级控制 | 可加 | 鱼塘等级先只加「可钓稀有度 + 钓鱼加成」，**不要碰鱼位**（否则与仓库双头管理） |
| 4 | 商店：鱼苗、食物、药剂、道具 | 已有 7 个条目（鱼饵/饲料/贝壳/珊瑚/喂食器/仓库/鱼缸） | 已具备 | 补「鱼苗直购」+「药剂」两类即可 |
| 5 | 抽奖与配对：珍珠抽碎片，配对产珍珠 | 珍珠只能卖 1 万，无抽奖、无繁殖 | **可加，且是最高价值的一条** | 珍珠改为抽奖券 + 新增繁殖系统 |
| 6 | 珍珠来源：以成熟收获为主，珍珠蚌低效 | 珍珠只来自钓鱼（15%×50%=**7.5%/次**） | 可加，但**当前数值已失控** | 先修平衡（见第二节），再改成成熟收获主产出 |
| 7 | 好友互动：偷鱼、喂食、放鲨鱼 | 纯本地存档，无账号体系、无服务端 | **不建议直接做** | 降级为「NPC 邻居鱼塘」本地模拟，保留偷鱼/放鲨鱼的乐趣 |

**一句话结论**：7 条里 5 条能落到现有架构，1 条已经具备，1 条（好友互动）在没有账号体系前不该硬做；但**在加玩法之前必须先修一个经济漏洞**，否则新玩法会加速崩坏。

## 二、P0 前置问题：钓鱼线目前是印钞机

这是本次评估顺带算出来的，比新增玩法更紧急。

### 实算（按当前 `config/` 配置）

单次抛竿的期望收益（用真实配置 + 20 万次抽样实算）：

| 产出 | 概率 | 单件价值 | 期望 |
|---|---|---|---|
| 鱼（成长随机，中位约 28） | 85% | 138 金币（R 档成鱼加权均价 288.8 × 平均成长折价 0.479） | 117.5 |
| 珍珠贝 → 珍珠 | 15% × 50% = 7.5% | 10,000 金币 | 750.0 |
| **合计** | | | **867.5 金币** |

成本：鱼饵 **10 金币**。
**净收益约 87 倍**。也就是说只要一直点「抛竿」，金币会指数级膨胀，鱼卵、鱼缸、仓库全部失去意义。
（对照：R 卵价 225 金币，养到成鱼卖 288.8 —— 正常循环一轮只赚 64 金币，钓鱼一次就赚 857。）

### 根因

珍珠被设计成「可卖 1 万金币的商品」，而获取成本只有 10 金币的鱼饵 —— 概率再低也压不住这个倍率。

### 参考玩法恰好给了正确解法

清单里写得很清楚：**珍珠主要用于抽奖（抽鱼碎片），珍珠蚌只是低效旁支**。也就是说珍珠本该是**抽奖货币**，不是可卖商品。

### 建议修正（三选一，推荐 A）

| 方案 | 做法 | 影响 |
|---|---|---|
| **A（推荐）** | 珍珠**取消直接卖钱**，改为抽奖券；珍珠蚌降到 3% 左右 | 一次解决套利，且与抽奖系统天然咬合 |
| B | 珍珠继续可卖，但价格降到 300~500 | 改动最小，但珍珠失去「稀有感」 |
| C | 珍珠贝概率降到 0.5%，珍珠维持 1 万 | 数字上能压住（期望约 40 金币/次），但玩家几乎见不到珍珠 |

若选 A，`pond.sellPearl` 保留但改为兜底出口（或直接下线），新增 `drawWithPearl`。

## 三、逐条落地方案

### 3.1 养鱼阶段化 + 成熟收获

**现状**
- `core/fish.js` 已有 `stageOf(growth)` / `stageName()`，阈值在 `economy.stage { juvenileAt: 35, adultAt: 100 }`
- 卖价 `sellPriceOf` 按成长折价（`minRatio 0.22`，`curveExp 1.15`），所以任何阶段都能卖
- 缺点：阶段只是个名字，**没有任何玩法意义**；玩家看不出「再等等更值钱」

**差距**：参考玩法是「单次收获、成熟才能收」，我们是「随时可卖」。

**不建议照搬硬门槛的原因**：开局只有 600 金币，R 卵约 225，鱼要养 75~150 秒。改成「必须成熟才能卖」会把新手卡死在没钱买卵的循环外，且与现有「卖鱼是唯一金币来源」的设计冲突。

**建议方案：软性引导，不做硬门槛**

1. 配置（`config/economy.js` 的 `stage` 增加）：
   ```js
   stage: {
       juvenileAt: 35,
       adultAt: 100,
       harvestBonus: 1.15   // 成鱼收获额外 +15%
   }
   ```
2. `core/fish.js` 新增：
   ```js
   function harvestReady(f) { return stageOf(f.growth) === 'adult'; }
   function harvestMul(f)   { return harvestReady(f) ? cfg.economy.stage.harvestBonus : 1; }
   ```
3. `sellPriceOf(f, shellLv)` 内乘 `harvestMul(f)`，**放在成长折价之后、取整之前**。
   注意：贝壳加成和收获加成都乘在卖价端，两者顺序无所谓（乘法可交换），但要保证 `matureValueOf` 不碰，否则卵价会跟着涨。
4. UI（`render/fishart.js` + `render/hud.js`）：成鱼头顶加一枚金色小穗标，选中时价签显示「已成熟 +15%」。

**工作量**：小。**风险**：需要同步更新 `shell-test` 里对卖价的断言。

### 3.2 鱼塘等级 + 碎片升级

**现状**
- `config/pond.js` 有 3 档塘（普通/稀有/传说），按 `rarity` 分档，`openMax: 1`
- `state.pondLv` 只在 `core/pond.js` 里被读，**没有任何写入路径** —— 目前是死字段
- 鱼位实际由 `storage.slotsPerTank() × tankCount` 控制

**关键取舍：鱼位归谁管**

参考玩法的「鱼塘等级 → 可养数量」如果照搬，会和现有仓库等级**双头管理鱼位**，两个系统都想改同一个数，后患无穷。

**建议**：
- 鱼塘等级只管三件事：**能钓到的稀有度 / 钓鱼产出加成 / 可解锁的塘数**
- 鱼位继续归仓库等级，不动

**方案**

1. `config/pond.js` 扩展：
   ```js
   levels: [
     { lv: 1, name: '普通鱼塘',   rarity: 'R',   catchBonus: 1.00, fragNeed: 0  },
     { lv: 2, name: '稀有鱼塘',   rarity: 'SR',  catchBonus: 1.10, fragNeed: 8  },
     { lv: 3, name: '传说鱼塘',   rarity: 'SSR', catchBonus: 1.20, fragNeed: 20 }
   ],
   fragment: { hookRate: 0.08 }   // 抛竿时额外获得 1 片碎片的概率
   ```
2. `core/state.js` 新增 `fragments: { pond: 0 }`
3. `core/pond.js` 新增：
   ```js
   function fragOf(state)                     // 当前碎片数
   function addFrag(state, n)                 // 加碎片（抛竿/收获/抽奖共用）
   function canUpgrade(state)                 // { ok, need, cur }
   function upgradePond(state)                // 扣碎片、pondLv+1
   ```
4. `cast()` 内：先判珍珠贝，再判碎片，最后才是鱼（顺序影响概率配比，务必按此写）。
5. 鱼塘页（`render/sheet.js` 的 `drawPond`）加升级按钮 + 碎片进度条。

**工作量**：中（主要在 UI 与命中区）。**风险**：`ui/layout.js` 鱼塘页要重排，`pond-test` 需要补升级路径断言。

### 3.3 珍珠双出口：抽奖

**现状**：`bag.pearl` 只有一个用途 —— `sellPearl()` 换 1 万金币。

**方案**

1. 新增 `core/draw.js`（不要塞进 `pond.js`，两者职责不同）：
   ```js
   // 一次抽奖消耗 1 颗珍珠
   function drawOnce(state)   // { ok, kind: 'frag'|'egg'|'item'|'nothing', payload }
   ```
2. 概率表放 `config/pond.js`：
   ```js
   drawTable: [
       { kind: 'frag', n: 1,  w: 55 },   // 鱼塘碎片
       { kind: 'egg',  rarity: 'R', w: 25 },  // 一颗 R 卵（直接进缸，需判鱼位）
       { kind: 'item', id: 'bait', n: 5, w: 15 },
       { kind: 'nothing', w: 5 }
   ]
   ```
3. **必须算期望**：一颗珍珠的机会成本不能高于它的获取成本（修完 P0 后约 100~200 金币/颗），否则没人抽。这也是为什么珍珠不能同时「卖 1 万」又「抽一次」—— 两个价格锚点会打架。

**工作量**：小。**风险**：抽到的卵要判鱼位满，满时降级为碎片，不能让玩家抽了个空。

### 3.4 配对繁殖

**现状**：完全没有。但 `config/traits.js` 里早已留了「速繁 / 双生」两条词条，`rollable: false` 占位注释写着「要等繁殖系统（M3）」。

**方案**

1. 新增 `core/breed.js`：
   ```js
   function canBreed(state, a, b)  // 同种、均为成鱼、均未在冷却、鱼位有余
   function breed(state, a, b)     // 消耗冷却，产出 1 条鱼苗 + 概率 1 颗珍珠
   ```
2. `config/economy.js` 新增：
   ```js
   breed: {
       cooldown: 600,        // 单条鱼两次繁殖间隔（秒）
       pearlChance: 0.35,    // 每次繁殖产珍珠的概率
       growthInherit: 0.15   // 鱼苗继承亲本成长的比例（给一点「养得久更划算」）
   }
   ```
3. 鱼对象加 `lastBreedAt`（存档字段，`save.js` 需同步）。
4. 开启 `traits.js` 的「速繁」：`breedCooldownMul`，让词条第一次有实际作用。
5. UI：仓库页/鱼缸详情里做「配对」入口 —— 推荐放**仓库页**，因为缸里点鱼已经是选中卖出。

**工作量**：中。**风险**：繁殖是无限产出，必须三道闸 —— 单鱼冷却 + 鱼位上限 + 亲本疲劳（连续繁殖后冷却递增，可选）。

### 3.5 商店补鱼苗与药剂

**现状**：商店 7 条已比较完整，缺「确定性买鱼」与「一次性增益」。

**方案**

1. **鱼苗直购**：本质是「买卵」的确定版，不新增品类，在鱼卵页每条鱼加一个「直购」按钮：
   ```
   直购价 = 成鱼卖价 × 1.15   （明显贵于抽卵，卖的是确定性）
   ```
   复用 `shop.eggPriceOf` 的取整逻辑，新增 `shop.buySpeciesDirect(state, speciesId)`。
2. **药剂**（消耗品，沿用 `consumable: true` 分支）：
   ```js
   { id: 'potion_grow', name: '生长药剂', desc: '全缸成长 +15%', consumable: true, price: {...} }
   { id: 'potion_mood', name: '安神药剂', desc: '全缸心情回满', consumable: true, price: {...} }
   ```
   药剂不是等级制，购买即生效，不入 `bag`。
3. **不引入「星钻」**：`economy.currencies` 里已经有 `s`（S 币）这个空壳，再开第三种货币只会增加认知成本。真要付费货币，等有广告/支付接入时再启用 `s`。

**工作量**：小。**风险**：药剂会稀释「养大才值钱」的节奏，数值要保守（+15% 而非翻倍）。

### 3.6 好友互动 → 降级为 NPC 邻居鱼塘

**现状**：存档是 `wx.getStorageSync` 纯本地，没有账号体系、没有服务端、没有防作弊。真做好友偷鱼，需要：账号/登录 + 云端存档 + 好友关系 + 服务端定时结算 + 防重复领取。这不是一个版本能完成的事。

**建议：先做单机版「邻居鱼塘」**

1. 新增 `core/neighbor.js`：
   - 用固定种子生成 3 个 NPC 鱼塘（名字、鱼、等级），**每次进入按时间推进成长**
   - 每日可偷 2 条（`state.neighbor.stealLeft`，按日期戳重置）
   - 可喂食一次，获得少量金币回礼
   - 可放鲨鱼：24 小时内让 NPC 鱼塘少 1 条鱼，玩家获得「放鲨鱼奖励」
2. `state` 新增：
   ```js
   neighbor: { day: '', stealLeft: 2, fedToday: false, sharkAt: 0 }
   ```
3. UI：仓库页下方加「邻居」入口，或主界面顶部加一个小图标。

**为什么不直接做真好友**：需要服务端与账号，属于另一个量级的工程；NPC 版能把「偷鱼 / 放鲨鱼」的乐趣先验证出来，等确认好玩再上云。

**工作量**：中（本地模拟逻辑不难，难在 UI 与每日重置的边界）。**风险**：单机「好友」体验偏薄，文案上要说成「邻居」而非「好友」，避免玩家误解。

## 四、建议分期

| 期 | 内容 | 理由 |
|---|---|---|
| **M10（先做）** | P0 珍珠平衡修正 + 成熟收获加成 + 鱼塘碎片升级 | 一个版本就能形成「钓鱼→碎片→升级塘→钓更好的鱼」的闭环，改动集中、风险可控 |
| **M11** | 珍珠抽奖 + 配对繁殖 | 两者共用珍珠，且繁殖能激活早已埋好的「速繁/双生」词条 |
| **M12** | 药剂 + 鱼苗直购 + NPC 邻居 | 都是增量，可独立上线 |
| **不做** | 真·好友互动、第三种货币（星钻） | 前者需要服务端与账号，后者增加认知成本而收益不明 |

## 五、存档兼容

- 当前 `saveVersion: 5`。本次扩展需新增 `fragments` / `neighbor` / 鱼对象 `lastBreedAt`，建议升到 **6**
- `core/save.js` 的 `deserializeV2` 里补默认值即可完成迁移（v4/v5 老档自动兼容）
- 所有新字段读取处必须夹紧，防止脏档：`fragments.pond` 取 `Math.max(0, ...)`，`pondLv` 夹在 `1..levels.length`

## 六、需要你决策的 5 个点

1. **P0 珍珠怎么修** —— 推荐 A：珍珠取消卖钱、改为抽奖券，珍珠蚌降到 3%。若你希望珍珠仍能卖钱，就走 C（概率压到 0.5%）。
2. **成鱼收获加成给多少** —— 建议 +15%。太高会让「随时卖」失去意义，太低又没人愿意等。
3. **鱼塘等级要不要管鱼位** —— 建议**不管**，鱼位继续归仓库，避免双头管理。
4. **繁殖产出** —— 只产鱼苗，还是「鱼苗 + 概率珍珠」？后者能让配对成为珍珠的稳定来源。
5. **NPC 邻居先做还是直接上云** —— 建议先 NPC；上云意味着要接账号体系，工作量是另一个量级。
